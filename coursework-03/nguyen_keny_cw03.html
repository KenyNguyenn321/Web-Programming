Exercise 1: External Style Sheet

This exercise changes the page's normal text color to dark red using an external CSS file.

CSS

body {
    color: darkred;
    font-family: Arial, sans-serif;
    line-height: 1.6;
}

Explanation

The document links to styles.css inside the <head>. The body selector applies the dark red text color to normal page text.

Exercise 2: Debugging CSS

The original CSS contained three mistakes that needed to be identified and corrected.

Mistake 1: Incorrect margin property

The original rule used margin-left: 20%; twice. The second declaration was corrected to margin-right: 20%;.

Mistake 2: Missing unit

The declaration font-size: 2.5 was invalid because it did not include a unit. It was corrected to font-size: 2.5em.

Mistake 3: Missing semicolon

The declaration width: 100% did not end with a semicolon. It was corrected to width: 100%;.

Corrected CSS

body {
    font-family: "Times New Roman";
    margin-left: 20%;
    margin-right: 20%;
    text-align: justify;
    background: ivory;
    color: red;
}

h1, h2, h3 {
    color: #ff0000;
    font-size: 2.5em;
    margin: 20px 0 20px 0;
}

.container {
    width: 100%;
    padding: 20px;
    box-sizing: border-box;
}

a {
    color: #0000ff;
    text-decoration: underline;
}

UG 01: Forensic Cascade Reconstruction

Three conflicting color declarations target the paragraph below through an element selector, a class selector, and an ID selector.

Prediction

The #cascade-target declaration should win because an ID selector has greater specificity than a class selector or an element selector. I predict that the computed color will be rgb(106, 27, 154).

This paragraph is the cascade testing element.

CSS Tested

p {
    color: #7f1d1d;
}

.cascade-sample {
    color: #176b4d;
}

#cascade-target {
    color: #6a1b9a;
}

Specificity Ranking

  1. #cascade-target: 1-0-0
  2. .cascade-sample: 0-1-0
  3. p: 0-0-1

Result and Reflection

The Computed panel reported rgb(106, 27, 154). The result matched my prediction because the ID selector had the highest specificity. The class and element declarations still matched the paragraph, but their color values were overridden.

UG 02: Pixel Budget Under Constraint

This investigation creates a panel with an outer width of exactly 420 pixels at a 900-pixel viewport without using width: 420px.

Content-Box Version

Content-Box Panel

The declared width controls the content area. Padding and borders are added outside that width. 

.content-box-demo {
    box-sizing: content-box;
    width: 40vw;
    padding: 27px;
    border: 3px solid #176b4d;
}

360px content + 54px padding + 6px border = 420px

Border-Box Version

Border-Box Panel

The padding and borders are included inside the declared width. 

.border-box-demo {
    box-sizing: border-box;
    width: calc(40vw + 60px);
    padding: 27px;
    border: 3px solid #176b4d;
}

40vw at 900px = 360px
360px + 60px = 420px

Result and Reflection

Both versions measured 420 pixels at a 900-pixel viewport. With content-box, padding and borders were added outside the content width. With border-box, those values were included inside the declared width.

UG 03: Breakpoint Failure Study

I tested the following three-card layout while reducing the viewport from desktop size. The first tested odd-numbered width that failed my layout test was 775 pixels.

Readability Test

The layout passes when every card remains inside its container without horizontal overflow. It fails when the minimum card widths force the grid beyond the available content width.

Structure

Semantic HTML organizes the page content.

Presentation

External CSS controls the visual design.

Testing

Responsive testing identifies layout failures.

Original CSS

.breakpoint-demo {
    display: grid;
    grid-template-columns: repeat(3, minmax(220px, 1fr));
    gap: 18px;
}

Cause

The three columns required 660 pixels and the two gaps required 36 pixels. The grid needed at least 696 pixels of internal space. At a 775-pixel viewport, the page margins and section padding left less than 696 pixels for the grid.

Repair

@media (max-width: 775px) {
    .breakpoint-demo {
        grid-template-columns: 1fr;
    }

    .breakpoint-card {
        min-width: 0;
    }
}

Result and Reflection

The repair stacked the cards at 775 pixels and removed the overflow. The desktop layout remained three columns at 1201 pixels, so the repair did not affect layouts above 1000 pixels.
