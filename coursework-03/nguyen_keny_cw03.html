Exercise 2: Debugging CSS

Finding and correcting three common CSS mistakes.

Debugging Analysis

Mistake 1: Incorrect margin property

The original rule contained margin-left: 20%; twice. The second declaration was corrected to margin-right: 20%;.

Mistake 2: Missing unit

The declaration font-size: 2.5 was invalid because it did not include a unit. It was corrected to font-size: 2.5em.

Mistake 3: Missing semicolon

The declaration width: 100% did not end with a semicolon. It was corrected to width: 100%;.

Corrected CSS

body {
    font-family: "Times New Roman";
    margin-left: 20%;
    margin-right: 20%;
    text-align: justify;
    background: ivory;
    color: red;
}

h1, h2, h3 {
    color: #ff0000;
    font-size: 2.5em;
    margin: 20px 0 20px 0;
}

.container {
    width: 100%;
    padding: 20px;
    box-sizing: border-box;
}

a {
    color: #0000ff;
    text-decoration: underline;
}

UG 01: Forensic Cascade Reconstruction

Three conflicting color declarations target the paragraph below through an element selector, a class selector, and an ID selector.

Prediction

The #cascade-target declaration should win because an ID selector has greater specificity than a class selector or an element selector. I predict that the paragraph's computed color will be rgb(106, 27, 154).

This paragraph is the cascade testing element.

Exact CSS Tested

p {
    color: #7f1d1d;
}

.cascade-sample {
    color: #176b4d;
}

#cascade-target {
    color: #6a1b9a;
}

Specificity Ranking

  1. #cascade-target: 1-0-0
  2. .cascade-sample: 0-1-0
  3. p: 0-0-1

Computed Result

The Computed panel reported rgb(106, 27, 154). The ID rule won, while the class and element color declarations were overridden.

Reflection

The browser result matched my prediction because the ID selector had the highest specificity. The Styles and Computed panels showed that the two lower-specificity declarations matched the paragraph, but their color values were overridden.

UG 02: Pixel Budget Under Constraint

This investigation creates a panel with an outer width of exactly 420 pixels at a 900-pixel viewport without using width: 420px.

Content-Box Version

At a 900-pixel viewport, 40vw equals 360 pixels. The horizontal padding adds 54 pixels and the borders add 6 pixels, producing an outer width of 420 pixels.

Content-Box Panel

The declared width controls only the content area. Padding and borders are added outside that width. 

.content-box-demo {
    box-sizing: content-box;
    width: 40vw;
    padding: 27px;
    border: 3px solid #176b4d;
}

360px content + 54px padding + 6px border = 420px outer width

Border-Box Version

After switching to border-box, the declared width includes the content, padding, and borders. The declaration calc(40vw + 60px) evaluates to 420 pixels at a 900-pixel viewport.

Border-Box Panel

The padding and borders are included inside the declared width instead of being added outside it. 

.border-box-demo {
    box-sizing: border-box;
    width: calc(40vw + 60px);
    padding: 27px;
    border: 3px solid #176b4d;
}

40vw at 900px = 360px
360px + 60px = 420px declared and outer width

Measured Results

  • Content-box outer width at 900px: 420px
  • Border-box outer width at 900px: 420px

Reflection

With content-box, padding and borders increase the rendered size beyond the declared width, so I included them in the arithmetic. With border-box, those values are included inside the declared width, which makes controlling the outer size more direct.
